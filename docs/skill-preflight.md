# DevOS Skills Preflight — обязательная проверка до Runner

Issue [#136](https://github.com/EmporioBreak/DevOS/issues/136).
Этот модуль выполняется Main Agent **до** запуска заранее объявленного
графа воркеров. Он **не** авторизует чат, не создаёт роли, ветки,
потоки, Issue или новых агентов. Прямое подключение к Runner —
отдельная задача #144.

## Приоритеты

Согласованное пользователем задание и безопасность DevOS →
полномочия Main Agent / DevOS Runner → обязательный **оригинальный**
Spec Kit stage → совместимые адаптации Superpowers → дополнительные
зарегистрированные навыки. Несовместимое обязательное требование
возвращается Main Agent для явного решения, а не игнорируется.

`src/skill-preflight.ts` принимает назначенную роль, фазу, точную версию
каждого выбранного навыка, `required`, `off`, этап оригинального
Spec Kit и закреплённый каталог. Это **локальный подготовленный**
контракт Main Agent; role/phase в нём не являются доказательством
доступа к MCP и не дают никаких серверных полномочий.

- Выбранный `required` нельзя пропустить или автоматически подменить.
  `off` несовместим с `required` и запрещает выбранный навык.
  Неуказанные зависимости и конфликты в обе стороны — блокер.
- Версия должна совпадать с закреплённой в Skills Library. Все
  вложенные файлы/ресурсы обязаны пройти существующую SHA-256 проверку.
- Оригинальные Superpowers `subagent-driven-development`,
  `requesting-code-review`, `executing-plans`, independent Git и
  workflow-оркестрация запрещены в автоматическом назначении.
  Четыре одобренных оригинальных качества (TDD, debugging, review
  reception, verification) разрешены без изменения upstream.
- Вместо оригинальных `brainstorming` и `writing-plans` используются
  **отдельные** `devos-brainstorming` и `devos-writing-plans`,
  причём только у Main Agent в фазе предварительного планирования.
  Любая попытка назначить их разработчику во время исполнения
  отклоняется.
- Для добавленных навыков дополнительно проверяются явные команды
  запуска собственных субагентов/второго workflow/Git switch/merge.
  Анализ текста не может гарантировать отсутствие любого скрытого
  противоречия: оригинал, происхождение, diff и назначение
  проверяются независимо.
- Поле `specKitStage` должно быть **указано явно**.
  Для `planning` допустимы только оригинальные SDD-этапы до
  реализации; для `execution` — `implement` или `converge`.
  Значение `null` разрешает pre-SDD разговор с Main Agent или
  самостоятельное независимое ревью, но не реализацию разработчиком
  и не шаг `devos-writing-plans`. Нельзя молча «забыть» обязательный
  Spec Kit этап.
- `config/devos-speckit-stage-pins.json` закрепляет SHA-256
  инструкций всех **девяти оригинальных SDD-этапов** установленного
  Spec Kit v1.1.2. Если обязательный `SKILL.md` изменился,
  отсутствует или ведёт через symlink за пределы checkout —
  проверка останавливает запуск.
- Возвращается только проверенный manifest с точными версиями,
  этапом и ролью. Ничего не добавляется автоматически.

## Тестовые проверки

```sh
npm run build
npx tsx --test tests/skill-preflight.test.ts
npx tsx --test tests/{skill-preflight,quality-methods,devos-brainstorming,devos-writing-plans,skills-library}.test.ts
```

Проверяются успешная одновременная работа оригинального Spec Kit и
Superpowers TDD/verification, версии, `required`/`off`,
зависимости, симметричные конфликты, запрещённая роль и stage,
сценарии изменённого pinned файла, подмены SDD skill, запрещённой
инструкции в пользовательском навыке и отсутствие скрытого
изменения списка выбранных skills.

Ограничения: это **preflight API**, а не живой запуск Runner.
Интеграция выбора `required/optional/off` по приоритетам
global/project/role/task относится к #138, раздача browser/Codex
к #139/#140, runtime lifecycle и enforced gate — к #144.
