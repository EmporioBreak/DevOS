# DevOS 2 — выбор навыков и настройки через ChatGPT

Issue [#138](https://github.com/EmporioBreak/DevOS/issues/138).
Состояние исходных skills, версий и хешей хранится в
`config/devos-skills.json` (#137). Пользовательские правила выбора
хранятся отдельно в **отслеживаемом Git**
`config/devos-skill-policy.json`. Начальный файл пуст;
пустой каталог навыков и список выбранных навыков допустимы.

## Уровни и приоритеты

Режимы: `required`, `optional`, `off`.

| Уровень | Контекст | Приоритет |
| --- | --- | --- |
| global | нет | самый низкий |
| project | `owner/repo` | выше global |
| role | `developer`, `reviewer` и др. | выше project |
| task | `owner/repo#issue` | самый высокий |

Одно правило для каждого `(scope, context, skillId)`; дубли
отклоняются. Заданное правилом на более специфичном уровне состояние
переопределяет менее специфичное, включая `off`.
При отсутствии правил режим **optional по умолчанию**:
Main Agent может запросить навык исходя из смысла задачи,
но ничего не активируется просто потому, что навык установлен.

`required` добавляется независимо от перечня предложенных optional.
Если источник недоступен, хеш изменён, инструкция несовместима,
роль/этап запрещены или конфликтует зависимость, вся подготовка
останавливается с явной ошибкой. `off` исключается полностью.
`optional` включается только по осмысленному назначению Main Agent
(`optionalCandidates`); любой отказ попадает в `skipped` с причиной.
Нельзя скрыто заменить оригинальный скилл адаптированным.

## Зафиксированный manifest воркера

`resolveWorkerSkills` (src/skill-policy.ts) выполняет совместимый
`preflightSkills` из #136, возвращает конкретную роль, текущий
Issue, стадию оригинального Spec Kit, точные версии, режимы,
причины назначения/пропуска и SHA-256 результата.
`saveWorkerSkillManifest` записывает разрешение только в
изолированное runtime-хранилище:

```text
.devos/skills/assignments/<url-encoded owner-repo>/<issue>/<worker-id>.json
```

Первое сохранение атомарно; повторное с **теми же байтами** допустимо.
Переназначить навыки уже зафиксированному воркеру внутри текущего
цикла нельзя. Идентичность и SHA проверяются при чтении.
Сам Runner из этого модуля не запускается; реальное применение
manifest к runtime — Issue #144. Локальные runtime-файлы не
нужно отправлять в GitHub.

## API ChatGPT

Два новых MCP инструмента доступны через существующий DevOS gateway:

- `devos_skill_policy_get({})`: read-only список 17 начальных
  skills с описаниями и версиями, текущие правила и fingerprint.
  Эта команда открывает компактную форму настроек в ChatGPT.
- `devos_skill_policy_set({skill_id, mode, scope, context?,
  expected_fingerprint})`: редактирует только одно правило
  `required / optional / off`; `context` требуется для project,
  role или task. Перед изменением нужно получить fingerprint через
  `devos_skill_policy_get`. Невалидные поля или устаревшая версия
  отклоняются. Сохранение использует атомарную запись и
  отдельную файловую блокировку, предотвращая конкурентное
  перезаписывание.

`ui://devos/skill-policy-v1.html` — небольшая форма с выбором
навыка, режима и контекста. При поддержке ChatGPT Apps она
использует `window.openai.callTool`; когда этой возможности нет,
инструменты доступны прямо в чате. У формы нет собственного
HTTP-endpoint или пароля.

**Безопасность:** оба инструмента и UI-ресурс требуют
`ChatAccessRegistry.isApproved` для *конкретного* ChatGPT-чата,
а не просто OAuth. Browser worker grant не даёт
права менять глобальные настройки. Для неразрешённого чата
сохраняется существующий lazy on-demand authorization;
на обычных инструментах новые App-шаблоны не появляются.
Меняется только Staging, не Production. Изменение настроек
отражается в локальной Git-backed конфигурации; commit/PR
для этих настроек — отдельное действие Main Agent, а не
автоматический push из формы.

## Проверки и ограничения

Unit-тесты проверяют приоритеты всех четырёх уровней,
отсутствие навыков, optional skip с причинами, обязательный
fail-closed, устойчивость версии, конфликтующие инструкции,
CAS-фингерпринт, блокировку одновременной записи, независимый
per-worker frozen manifest и защиту от подмены SHA.
Реальный MCP SDK integration тест проверяет owner
get/set/UI, отсутствие повторной авторизации в разрешённом чате,
а также, что другой чат с тем же OAuth client
**не получает** policy или form.

Прямой тест в приложении ChatGPT на iPhone и реальное использование
кнопок формы клиентом остаются частью #151; unit/MCP SDK
не следует выдавать за фактически подтверждённое поведение iOS.
Окончательная привязка выбора skills к Issue/Runner — #143/#144.
