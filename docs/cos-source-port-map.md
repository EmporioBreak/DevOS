# COS source-to-DevOS port matrix (Issue #246)

Upstream **Chat on Steroids**: [totec448-spec/chat-on-steroids at f64ee51bf33a0ef194b7b0849d52c4aef9ac07d9](https://github.com/totec448-spec/chat-on-steroids/tree/f64ee51bf33a0ef194b7b0849d52c4aef9ac07d9) (2026-10-12 source pin; MIT license). DevOS branch: `architecture/dynamic-agent-runtime-246`, draft PR #247.

## Interpretation of the requested migration

This is a **source-level port**, not a greenfield implementation inspired by COS terminology. COS and DevOS are both TypeScript, so the target conversion is from the Electron/Chrome extension and its bridge/provider surfaces into DevOS's Node.js/Camoufox/MCP/local Codex integration. All material source state transitions, failure models, tests and invariants should be traced to their original implementations. Preserve differences only when required by DevOS's task-scoped GitHub/Spec Kit/skills/security boundaries.

**Do not claim completion from this document or a passing unit suite:** the table distinguishes algorithms already adapted from parts requiring code/host integration.

## Intentional deviations

- COS's `assertRoute` restricts workers to messages addressed to the prime and only the prime may `spawn`; **replace its star topology with authenticated direct peer-to-peer routing and policy-limited specialist admission**.
- COS uses broad app-specific browser/session roots; DevOS must bind every operation to repo + Issue + PR + signed task policy + exact agent identity and immutable saved browser/Codex session, not a friendly `worker-1` label.
- COS does not perform DevOS Spec Kit, GitHub PR, signed independent-review and Main Agent final-acceptance policy; these remain DevOS-specific.
- Do not copy COS's Electron/extension UI or start an alternate browser profile. Host adapters must reuse existing project Camoufox process and original provider send authority.
- CoS-inspired code must retain MIT attribution and the reviewed source pin; **a new source revision is a separate reviewed change**, not an automatic unpinned upgrade.

## Critical acceptance left before replacement

1. Connect the implemented two-phase `requestSpawn/claimSpawnBootstrap/bindSpawn` to real browser/Codex bootstrap under the existing authenticated custody owner; retain verified host-first binding. `admit()` is still a legacy existing-session admission route and must not be mistaken for new provider creation.
2. Wire the new persisted `wakeCommands` / `DynamicWakeDispatcher` protocol into the **existing** single Camoufox browser command owner, including exact page/turn identity, cancellation and late-ACK handling and context-ceiling terminal-worker fencing. Mock host verification is not a real provider/browser receipt.
3. Finish/reports, independent reviewer and Main Agent handoff in the same Issue/PR without fixed `worker.on` graph.
4. Complete **automatic** quiescent native supervisor recovery and power-loss/multi-reclaimer conflict testing. `recoverDynamicStoreLock` is manual-host-authorized and tests actual SIGKILL; no safe unattended owner adoption yet. Provider message-id correlation and retention remain subject to real host controls.
5. Real DevOS MCP/Camoufox/Codex integration, signed grant tests, preservation of all v1 in-flight saved tasks.
6. Actual `npm run build`, complete affected/full test suite, independent code/security review and headed signed-in two-Issue provider E2E; hosted Linux full suite has existing failing MCP/browser cases not yet baseline-attributed. Only then a separately authorized Production cutover.

## DevOS-specific trust and executor integration (not present in COS)

- `src/dynamic-agent-policy.ts`: seal and verify one owner-approved immutable task/role/skill/budget policy with a separate HMAC key domain from v1 Runner; no model-generated `policyId` grants permission. `sealedDynamicPolicyVerifier` can be used as the real `DynamicTrustBoundary.verifyPolicy` implementation. Actual owner approval must still originate from the trusted host.
- `src/dynamic-agent-devos-executor.ts`: adapt authenticated execution requests to the **existing** DevOS `Executor.run`, `WorkerRequest.reportTurn` and mandatory signed Codex skill assignments. Saved Codex threads and ChatGPT conversations are reused, never changed or silently restarted. Native provider IDs and exact worker-grant identity must still be independently supplied by host callbacks.
- `src/dynamic-agent-lock-recovery.ts`: host-maintenance-only SIGKILL lock recovery with process lifetime identity and quiescence guard, never blind stale-timeout unlock. Production native supervisor and multi-process recovery fences are not yet integrated.
