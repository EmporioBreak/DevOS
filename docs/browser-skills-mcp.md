# DevOS 2 — навыки ChatGPT-воркера через MCP

Issue [#139](https://github.com/EmporioBreak/DevOS/issues/139). Этот модуль
предназначен **только для заранее объявленных DevOS browser workers**;
не превращает DevOS Runner в планировщик и не создаёт дополнительных
воркеров или GitHub Issues.

## Протокол

- `devos_skill_manifest({})` — список закреплённых навыков и ресурсов
  текущего воркера (включая обязательный оригинальный этап Spec Kit).
- `devos_skill_search({query})` — поиск только по назначенным навыкам.
- `devos_skill_read({skill_id,resource})` — полный текст `SKILL.md`,
  вложенных `references/*`, `scripts/*` и других ресурсов с точной
  SHA-256, версией и форматом `utf8`/`base64`.

Все ресурсы доступны только для **чтения**. Возвращённый текст скрипта
не выполняется сервером; при необходимости локальных программ воркер
следует заранее разрешённому DevOS fallback, а не запускает собственные
субагенты или независимый execution engine.

## Авторизация — два независимых доказательства

1. MCP gateway получает настоящую сессионную идентичность запроса и
   проверяет `ChatWorkerGrantRegistry.activeIdentity`: HMAC-подписанный
   grant активного браузерного чата, точную задачу, turn, worktree/task
   lock с живым PID и соответствующую сохранённую conversation.
   Значения `repo`, `issue` или `worker_id`, предложенные моделью,
   не превращаются в полномочия.
2. Подписанный **отдельным ключом, производным от локального owner secret**
   `ResolvedWorkerSkills` содержит точный `workerId`, Issue,
   original Spec Kit stage, выбранные версии и режимы. Этот manifest
   создаёт Main Agent до запуска воркера. Gateway не принимает unsigned
   файл для browser skill delivery и не позволяет в продолжении
   менять назначение.

Файл назначения хранится локально и не попадает в Git:
`.devos/skills/assignments/<encoded repo>/<issue>/<worker>.json`.
Для browser delivery применяется format `version: 2` с HMAC и
вложенным `manifest`; старый формат без HMAC может продолжать
использоваться только в локальных legacy-тестах/контрактах, **не**
для доступа браузера. Реальное взаимодействие Runner с сохранением
manifest — отдельная задача #144.

## Защита ресурсов

Каждое чтение сверяет `version` с проверенным Skills Library,
контрольную сумму исходного Spec Kit stage, SHA-256 каждого
файла и запрет symlink/path traversal за пределы trust root.
Библиотека выдаёт только заранее перечисленные в manifest ресурсы,
а неожиданный файл либо изменение pinned source приводят к отказу.
Вещание в ChatGPT ограничено 1 MiB на ресурс.

Upstream cache по умолчанию находится в
`~/.devos-staging/upstream` и может задаваться
`DEVOS_UPSTREAM_ROOT`. Перед production release #154 необходимо
настроить путь к **установленной локальной копии официальных
источников**, а не к staging cache.

### Ограничение текущего registry (важно для дальнейших Issues)

В `config/devos-skills.json` пока один закреплённый `version`
на `skillId`. Если владелец обновил оригинал посередине выполнения
Issue, старое подписанное назначение **отказывает в доступе**,
а не получает незаметно новую версию. Это fail-closed, но не
полноценное параллельное обслуживание *разных версий одного skill*.
Для этого потребуются версионированные snapshots в #141/#144 и
отдельные интеграционные тесты. Разные Issues с разными выбранными
навыками уже изолированы.

## Проведённые проверки

Тесты `tests/browser-skill-delivery.test.ts`:
две независимые задачи, два набора навыков, оригинальный Spec Kit,
чтение полного `SKILL.md` и вложенных reference/shell-script,
запрет исполнения, поиск, отказ чужому skill/Issue, запрет
неверного resource/пути, отказ при подмене HMAC, секрета,
SHA-256, оригинального Spec Kit и версии каталога.

`tests/chat-worker-grants.test.ts` проверяет сессионное
авторизующее доказательство отдельно, включая истечение TTL,
враждебное утверждение о роли/turn, отсутствие живого владельца
и отзыв worker grant.

Проверки через *реального ChatGPT browser worker*, подключённого
к отдельному Staging MCP через Cloudflare, ещё **не проведены**
(запланированы #150/#151 вместе с #144). Эти тесты
не следует выдавать за подтверждённое App/iPhone или
end-to-end поведение.
