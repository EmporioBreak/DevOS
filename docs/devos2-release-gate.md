# DevOS 2 — блокирующий release gate и безопасный rollback (#154)

Состояние на **2026-10-10:** **DevOS 2 развёрнут в Production по прямому разрешению владельца, но ПРОДУКТОВАЯ E2E-ПРИЁМКА ЕЩЁ ЗАБЛОКИРОВАНА**. GitHub `main` и работающий Production совпадают на merge-коммите `650865bcf0ff0e31ab699f3c045e98e1f7e67d6b` (предыдущий SHA для отката: `7acda9327d4d878522fecb516f61d0f5a3abccdc`). Существующие ngrok, `.devos` и общий Camoufox сохранены; отдельный Staging MCP отключён. Живые E2E #150–153 и проверка Web/iPhone #151 **не приняты**. Автоматические тесты 566/566 и post-deploy 23/23 проходили, но они не заменяют живую проверку. Epic #121 и Issue #154 остаются открыты.

## Неподменяемые условия продвижения

Модуль `inspectDevos2ReleaseReadiness` проверяет исходную машинную матрицу Epic #121: **11 реальных критериев**: **9 предрелизных** по #150–153 и **2 пострелизных** по #154. До релиза проверяются только 9 обязательных E2E: требовать пострелизную проверку до выкатки означало бы невозможный замкнутый цикл. После релиза отдельный `inspectDevos2PostReleaseEvidence` проверяет два оставшихся пункта. Для каждого требуется **отдельное**, независимо подтверждённое провайдером свидетельство фактического выполнения, привязанное к **точному Git SHA релиз-кандидата**. Авторский текст модели, фиктивный `sourceRef`, зелёный fixture или устаревший head — не подтверждение.

**Решение владельца от 2026-10-10:** отдельный backup не является обязательным release gate. Исходники и история коммитов сохранены в GitHub. При ошибке выполняется возврат к заранее проверенному Production Git SHA; повторная авторизация MCP/ChatGPT допустима и обычно быстрая. Рабочие OAuth/session, конфигурацию ngrok и существующий профиль Camoufox **не удаляем и не перезаписываем**, не переносим туда данные Staging. При этом возврат к Git SHA **не восстанавливает автоматически** повреждённые локальные состояния: это известный принятый риск, а не гарантия сохранения всех сессий. PR #206 с отдельным backup-инструментом исключён из основной релизной цепочки и остаётся необязательным.

Нельзя публиковать приватные пути, OAuth-токены, cookies, пароли или conversation URLs в Issue/PR. Проверки девяти реальных E2E и ручное решение владельца остаются обязательными.

Статус `blocked` означает, что перенос запрещён. Даже если ВСЕ подлинные проверки приняты, ответ — **`ready_for_owner_release_decision`**, но всегда `mayMerge:false`, `mayTouchProduction:false`, `mayCloseEpic:false`. После этого Main Agent предъявляет владельцу точный релиз-пакет и отдельно получает явное решение. Контракт проверки не является инструментом автоматического merge или выкладки.

Проверка изолированной DevOS 2 worktree без секретов, побочных эффектов, вмешательства в запущенный Production или запуска browser workers:

```sh
npm run build
npx tsx --test tests/devos2-release-readiness.test.ts
npx tsx scripts/devos2-release-preflight.ts
# ОЖИДАЕМО до реальных E2E: status=blocked, exit 2
```

CLI выводит лишь ID незакрытых критериев и текущий commit, **не** приватную копию, адреса ngrok/Cloudflare и OAuth.

## Когда живые блокеры будут разрешены — последовательность V06

1. **Main Agent проверяет реальную матрицу:** оригинальный Feature SDD, Bugfix RED/GREEN и Assess в отдельно проверяемом ChatGPT Project/безопасном тестовом маршруте без тестового MCP; GitHub связка Issue/PR, независимый reviewer→changes_requested→rework→owner handoff, конкретный browser→Codex `needs_local_worker` и source pins. Отдельно ChatGPT Web и iPhone: native App/Safari, OAuth, отсутствие лишних authorization forms, default-deny чужого чата.
2. Зафиксировать конечные Git SHA всей stacked-цепочки и PR review; пересобрать кандидат в изолированной worktree из единой проверенной базы, повторить `npm run build`, полный `npm test` и разрешённые безопасные host-smoke без поднятия второго тестового MCP. Для недоступных живых E2E зафиксировать `blocked`, не симулировать PASS. Не менять SHA оригинальных upstream автоматически.
3. **До изменений** сверить актуальный `main` и GitHub `origin/main`, сохранить точный Git SHA, подтвердить наличие истории коммитов и возможность безопасного возврата к нему. Проверить, что release не предусматривает удаления/перезаписи `.env`, `.devos`, OAuth/client/worker state, пользовательского browser profile, либо переноса Staging URL/портов. Отдельный приватный backup допустим по желанию, но не требуется.
4. **Только после явного решения владельца** проводить контролируемое обновление с предсказуемой остановкой лишь собственного Production runtime. Переносить проверенный код; не заменять локальные настройки и реальный Camoufox profile. Если авторизация всё же сбросится, повторная авторизация допускается; никогда не обходить MCP default-deny или worker-grant проверку.
5. После релиза настоящий smoke: Production ngrok/MCP, ChatGPT Web+iPhone approved/unapproved chat, реальный Mac file/shell, Project conversation, worker grant, Codex fallback и отсутствие повторных карточек. Новую авторизацию при сбросе разрешено пройти штатной формой; нельзя обещать сохранение активных логинов. Сохранить внешние доказательства в Issue/PR, не их секретное содержимое.
6. При критическом нарушении остановить только runtime релизной версии, вернуть код к сохранённому Git SHA без автоматического `reset --hard`/`rm -rf` и без затрагивания `.env`, `.devos`, OAuth и Camoufox; после запуска проверить старые Web/iPhone чаты, при необходимости заново авторизовать текущие чаты. Не обещать, что Git восстановит локальные task sessions или cookies.
7. Только после успешной пострелизной независимой проверки Main Agent записывает фактические SHA, результаты и ограничения в #154/#121 и предлагает закрытие Epic. Даже идеально прошедшие unit tests **не** являются post-release приемкой.

## Зафиксированные технические блокеры

- **#150**: первый реальный Staging browser worker test потенциально отправил QA-сообщение, но не вернул подтверждённый terminal ответ в пределах deadline. Тот же ход не повторялся; действует локальный Staging one-shot guard. Значит, ни полный Feature, ни Bugfix, ни Assess через настоящий ChatGPT не засчитаны.
- **#151**: ранее тестировался публичный Cloudflare Staging MCP/OAuth, но отдельный Staging plugin не был надёжно привязан к ChatGPT Web/iPhone. По решению владельца тестовый MCP теперь **отключён**, повторно его не запускать; Web/iOS верификация всё ещё не получена.
- **#152**: 73/73 безопасных synthetic/host-local tests пройдены, но фактический end-to-end разрыв сессии и восстановление ChatGPT соединения ещё не показаны.
- **#153**: русское руководство и проверенные примеры созданы; без живого user walkthrough конечная приёмка не завершена.

**Следствие:** #154 и Epic #121 остаются открыты до реальной независимой приёмки. Production уже обновлён по решению владельца; его нельзя считать испытанным на Web/iPhone или на end-to-end воркерах только по HTTP/status тестам. Никаких ссылок/токенов на приватные состояния в публичном GitHub.

## Тестовый MCP отключён по решению владельца

Отдельный тестовый MCP/Staging Cloudflare остаётся отключённым. Операции на Mac и локальные проверки запускаются через исходный Production Desktop Commander MCP **уже с развёрнутым кодом DevOS 2**. Обязательные живые проверки #150–153 требуют явно согласованного альтернативного безопасного маршрута и самостоятельного provider-backed доказательства; отключение Staging **не означает**, что они прошли. Тесты на фикстурах и успешный `npm test` не заменяют приёмку Web/iOS.

## Реальный Production baseline после установки (не полный E2E)

Следующий read-only smoke предназначен **для уже развёрнутого Production**:

```sh
node scripts/devos2-production-postrelease.smoke.mjs
npx tsx --test tests/devos2-production-postrelease.test.ts
```

Запускать из чистого Production checkout. Скрипт не вызывает Runner, не открывает
Camoufox, не регистрирует OAuth-клиентов, не передаёт действующие bearer токены,
не запускает второй MCP и не изменяет Git. Он проверяет совпадение локального
`main` с GitHub, наличие профиля без чтения cookies, отключённый порт 8788,
локальную и публичную HTTPS доступность, OAuth discovery и отказ `401/403`
анонимному/неверному bearer на `POST /mcp`. Только имена проверок,
статусы и публичный Git SHA попадают в отчёт: приватных hostname, OAuth
ресурсов, chat URL, токенов или содержимого файлов он не печатает.

`baseline_pass` означает **только** transport/install baseline. Он принципиально
содержит `fullProductAcceptance:false`, `independentlyVerifiedE2e:[]` и
все 9 неподтверждённых live gates. Нельзя использовать этот JSON вместо
provider-attested доказательства реального worker turn, Web/iPhone Apps,
чужого ChatGPT-чата или финальной приёмки. После установки
`devos2-release-preflight.ts` продолжает показывать `blocked` для
непрошедших E2E — теперь это **статус приёмки**, а не утверждение, что код
не развёрнут. Зафиксировать baseline в #154 без секретов.
